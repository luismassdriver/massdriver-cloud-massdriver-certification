# massdriver-certification (Massdriver bundle)

Runs the certification quiz app on a Kubernetes cluster and points it at a Postgres database, both supplied by the environment it is dropped into. Written for Massdriver v2 and the `citizens` catalog: it follows the same shape as the catalog's `demo-app` (Helm chart installed by OpenTofu, ALB ingress on EKS Fargate).

## Dependencies

| Dependency | Resource type | What it provides |
| --- | --- | --- |
| `runtime` | `kubernetes-cluster@0.0.0` | API server, CA and token for the cluster; namespace (defaults to `apps`) |
| `database` | `postgres-database@0.0.0` | Host, port, database, username, password → `DATABASE_URL` |

## Resources

| Resource | Resource type | Contents |
| --- | --- | --- |
| `url` | `web-endpoint@0.0.0` | `url` (the public URL) and `hostname` (the load balancer's DNS name) |

## What gets deployed

A Helm chart in [`chart/`](chart/): one `Secret` (database URL, Auth.js secret, optional OAuth credentials), a `Deployment`, a `Service`, and an `Ingress` of class `alb` with `target-type: ip` so the AWS load balancer controller on the Fargate cluster creates an internet-facing ALB that talks straight to the pods. Health checks hit `/api/health`.

`AUTH_SECRET` is generated by OpenTofu (`random_password`) on the first deploy and kept in state, so nobody has to mint one by hand. The app runs with `AUTH_TRUST_HOST=true`; when `public_url` is empty it builds links from the incoming request's host, which is the ALB address, so the first deploy works with no DNS at all. Set `public_url` once a real domain points at the load balancer.

## Parameters

| Param | Notes |
| --- | --- |
| `image.repository` / `image.tag` | Must be pullable without credentials (the GHCR package must be public) |
| `replicas` | 1 for staging, 2+ for anything that should roll without a gap |
| `resources.cpu` / `resources.memory` | Per pod; Fargate rounds up to the nearest size |
| `configuration.dev_login` | Passwordless email sign-in. Staging only. |
| `configuration.public_url` | Optional; see above |
| `configuration.google_oauth` / `github_oauth` | Optional client id + secret pairs; a provider appears only when both are set |

## Publish

Massdriver v2 publishes bundles into OCI repositories that must exist first. From the repo root, with `MASSDRIVER_API_KEY` and `MASSDRIVER_ORG_ID=citizens` set:

```sh
mass repository create massdriver-certification -t bundle   # once; errors if it already exists, which is fine
mass bundle build   --bundle-directory massdriver
mass bundle publish --bundle-directory massdriver
```

The GitHub Actions workflow in `.github/workflows/ci.yml` does exactly this on every push to `main`, after building and pushing the container image.

## Deploy

In the Massdriver UI, on the environment's canvas: add `massdriver-certification`, link `runtime` to a `kubernetes-cluster` (for example `d2pmdsi-dev-runtime`), link `database` to an `aws-rds-postgres` instance, pick the **Staging** preset, deploy. The database must accept connections from the cluster's pods (the Postgres bundle owns that side). After the first deploy the `url` resource holds the ALB address.
